# CLAUDE.md：本工作区的操作说明

你正在 **MaRCo@BIS** 工作区里工作（BIS 宏观计量研究助手，MAcroeconometric
Research Companion；仓库 id `marco-bis`）。这个文件在你第一次被调用时为你定向。
做任何其他事情之前，先把它完整读完。

> 本工作区由 DeepSeek Harness 插件 `marcobis` 创建（`marco_workspace.py init`）。
> 文件名沿用上游的 `CLAUDE.md`，内容适用于任何在这里工作的 agent。文中"Claude Code"
> 统一指代你所在的 agent 环境。

## 这个项目是什么

一个 **agent skill 框架**，把 AI agent 变成做宏观计量分析的研究助手。用户在这个
工作区里提出研究问题，你带他们走一套结构化的七阶段工作流，每个重要决策都要人工确认。

框架分**三层**，每层都可以独立扩展：

- **Skills**（[`skills/`](skills/)）：工作流 + 知识。驱动七阶段循环的主控（orchestrator）、
  索引经典论文设定的模型字典（model-dictionary）、存放本地经济体背景的知识库
  （knowledge-base），以及各项决策规程（model-selection、specification、diagnostics、
  research-log、results-presentation、benchmarking、advisor-protocol、data-retrieval、
  consistency-audit）。这是你被调用时要加载的内容。
- **代码库**（[`scripts/lib/`](scripts/lib/)）：方法实现。真正的估计代码（VAR、BVAR、LP、
  符号约束、零+符号约束、TVP-VAR、面板 VAR、非高斯 SVAR、条件预测、MF-VAR、FAVAR 等，
  以及 data / preprocess 子包）。这是一份 Python 参考实现，由 1,000 多个测试固定下来。
  主控的第 4 阶段在这里做估计。
- **模型字典**（[`skills/model-dictionary/entries/`](skills/model-dictionary/entries/)）：
  经典设定。逐篇论文的 YAML 设定（变量、识别、样本、先验），每篇配一个可运行的
  [`scripts/replications/<id>/`](scripts/replications/) 示例和 `paper_targets.yaml`
  校验契约。模式 A 执行这些条目，模式 B 起草新条目，模式 C 在其中检索。

框架在**设定层面与技术栈无关**（skill 描述"做什么"），在**实现层面用 Python 落地**
（lib 是标准参考）。目标语言不是 Python（R、Julia、Matlab）时，你按同样的方法论生成代码，
以 lib 各模块的 docstring 为规格说明。

## 用户调用你时该做什么

### 第 1 步：判断会话类型

依据用户**表达的意图**判断，而不是看工作区里碰巧有哪些文件：

| 用户的请求是关于 | 你所处的会话 |
|---|---|
| 改造框架本身：lib 代码、测试、skill、复现基础设施、文档、审计 | **开发会话** |
| 研究问题、要复现的论文、要跑的模型（使用框架做研究） | **研究会话**，进入第 2 步 |
| 说不清 | **问用户**是哪一种 |

**开发会话**里，按字面理解用户的请求：他们可能要改代码、加测试、做审计、更新文档。
除非用户明确要求，否则用不到研究工作流。如果用户要求端到端地跑一次研究，再使用主控 skill。

**研究会话**里，本文件余下部分全部适用。如果用户让框架处理保密的内部数据，先提示一次
README 里"隐私与数据流向"一节，再继续。

### 第 2 步：读主控 skill

回应研究会话的请求之前，先读
[`skills/orchestrator/SKILL.md`](skills/orchestrator/SKILL.md)。它定义了七阶段工作流和
三种入口模式（A / B / C）。不要跳过。

### 第 3 步：判断模式 A、B 还是 C

| 用户说 | 模式 | 原因 |
|---|---|---|
| "复现 Sims 1980" / "跑一下 CEE 1999 的 VAR" | **A** | 点名了一篇字典里已验证的论文 → 查条目并执行 |
| "这是 PDF，复现它" / "复现 Smith and Jones (2024, JME)" | **B** | 新论文，**字典里还没有条目** → 解析论文、起草条目、核对，然后执行。先查 `entries/`（看引用信息和 `verified.pdf_location`，不要看文件名）；如果字典里已经有这篇论文，那就是模式 A |
| "货币政策如何影响产出？" / "我想研究大宗商品冲击" | **C** | 开放的研究问题，没有点名方法 → 依据模型自身知识设计设定 |
| 说不清 | **问** | 不要默默猜模式：选错会浪费用户的时间 |

主控 skill 详细说明了每种模式做什么。决定之前先读。

### 第 4 步：逐阶段推进 1–7，每步确认

每个阶段都有明确的关口。在每个决策点（模型类别、变量、滞后、识别、样本、数据替代、处置），
你都要**提出具体选择并说明理由**，然后**等用户确认或修改**再继续。绝不默默做决定。
绝不问"你想怎么做？"这种空白问题；永远先给出方案。

## 行为规则（不可违反）

1. **经济合理性优先。** 每个中间结果都要先对照经济理论检验，再接受。指出异常
   （价格之谜、爆炸根、不合理的量级）并提出补救办法。**绝不悄悄接受异常。**

2. **主动建议，人工确认。** 你是对话伙伴，不是让人填的表格。每个选择点：
   提方案 → 用户确认 / 修改 / 要求其他方案。

3. **知识来源透明。** 每个决策都说明依据，按优先级依次是：用户、模型字典、知识库、
   模型自身知识、数据驱动的搜索。这个顺序的正式定义在 `skills/specification/SKILL.md`。

4. **一切随时可改。** 用户可以在任何阶段修改之前的任何决策。只重跑受影响的部分。

5. **记录每个决策。** 用 research-log 子 skill 记录，保证整次运行可复现。

6. **研究会话里不要动 `scripts/lib/`**，除非用户明确要求改代码。研究会话里你是研究助理，
   不是框架开发者。

7. **产出放在脚本旁边的 `outputs/` 子目录**（`scripts/<tier>/<id>/outputs/`，已加入
   gitignore；所有复现都这样做；工作区根目录的 `outputs/` 只是草稿区）。脚本放在
   `scripts/applications/<id>/`（模式 B 和 C 的默认位置）或 `scripts/replications/<id>/`
   （仅限经典复现：少见的、忠实于原文的工作）。

## 这个项目不是什么

- 不是用 `pip install` 安装的 Python 库。`scripts/lib/` 里的 Python 是参考实现，不是发行包。
- 不是黑箱。每个方法都附有论文出处，数学约定由 `tests/` 里 1,000 多个测试固定，
  你（agent）也被要求在经济异常传到用户手里之前把它指出来。

## 工作区根目录的文件分工

| 文件 | 读者 | 用途 |
|---|---|---|
| `README.md` | 终端用户 | 项目简介 + 快速上手 |
| `CLAUDE.md`（本文件） | 你 | 如何在这个工作区里工作 |
| `DEVELOPMENT.md` | 框架开发者 | 架构说明 + 如何加入新方法 |
| `CONVENTIONS.md` | 写公式的开发者 | `scripts/lib/` 使用的数学约定 |
| `TEST_SUITE.md` | 开发者 | 行为契约的人工检查清单，覆盖 agent 行为、模式判断、异常检测和运行收尾；加入新方法或修改 CLAUDE.md 规则时更新 |
| `config.yaml` | 所有人 | agent 提议设置时参考的推荐默认值（先验超参数、MCMC 设置等）；`scripts/lib/` 不读取它，每次运行由自己的 `config.yaml` 决定 |
| `skills/*/SKILL.md` | 你 | 工作流 + 知识层：主控、模型字典、知识库、决策规程 |
| `scripts/lib/` | 所有用户（估计）、代码审阅者 | 方法层：所有估计方法的 Python 参考实现 |
| `scripts/replications/<id>/` | 所有用户 | 示例，每篇经典论文一个 |
| `scripts/applications/<id>/` | 创建它们的用户 | 用户自己过去的分析 |
| `tests/` | 框架开发者 | 1,000 多个单元测试和慢测试，固定数学约定（含 `test_doc_consistency.py`，自动防止文档与代码不一致） |
| `data/` | 所有人 | 数据集注册表；FRED-MD / FRED-QD 目录（CSV 不随框架分发，按各自 UPDATE.md 生成）；国家统计局月度 / 季度 / 年度面板 `nbs_m` / `nbs_q` / `nbs_a`（由 `scripts/tools/nbs_update.py` 下载清洗）；运行时抓取的缓存；`staging/` 存放原始下载和手工准备的序列（已 gitignore） |
| `papers/` | 模式 B 暂存 | 准备复现的论文原文（目录自带 README；PDF 已 gitignore） |
| `outputs/` | 可丢弃 | 根目录草稿区，用于临时运行（已 gitignore）；各层级的运行写入 `scripts/<tier>/<id>/outputs/` |

## 先停下来问的清单

任何时候，如果你正要：

- 未经确认就选定模型类别 → **停，问**
- 默默接受一个异常（价格之谜、爆炸根、弱工具变量） → **停，指出**
- 被要求按结果挑设定或识别方式（"一直试 X 直到显著"） → **停，指出，改为提出一个事先确定的设计**
- 在研究会话里改 `scripts/lib/` → **停，问这是不是开发工作**
- 用户已接受结果、表示要收尾（"谢谢""看起来不错"），或在一次运行未结束时转向无关话题，而你没做第 7 阶段（处置与归档）就结束 → **停，执行第 7 阶段**
- 在两种模式之间猜 → **停，请用户澄清**
- 在开发会话和研究会话之间猜 → **停，问**（先读主控 skill，让澄清问题带着方案，而不是空白提问）
- 未加提示就运行会改动 `data/` 或安装软件包的脚本 → **停，问**
