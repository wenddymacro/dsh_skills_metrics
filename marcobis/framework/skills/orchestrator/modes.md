# 三种入口模式：参考说明

本文展开 [SKILL.md](SKILL.md#三种入口模式) 中的简要概述。分流新会话、依据论文起草新的字典
条目，或判断是否需要模式转换时阅读。

## 模式 A：字典执行（确定性）

用户点名的论文、方法或设定在 [`skills/model-dictionary/entries/`](../model-dictionary/entries/)
中有经过核验的条目。例如：

- "复现 Sims 1980。"
- "用 FRED 数据跑 CEE 1999 的 VAR。"
- "按 Uhlig 的约束估计一个符号约束 VAR。"

**路径：**

1. 按 id 或引用信息查找匹配的条目。有多个候选时，列出来请用户挑选。
2. **在两个层级中查找**可运行的目录：
   - [`scripts/replications/<id>/`](../../scripts/replications/)（经典，排在前面）
   - [`scripts/applications/<id>/`](../../scripts/applications/)（你过去的工作）

   任一层级有目录时，确定性路径是 `python scripts/<tier>/<id>/replicate.py`。
   两个层级都匹配时，列出来让用户选；默认是经典。确认用户想要的数据替代，然后运行。
3. 两个层级都没有目录时，按 [`scripts/replications/` 的约定](../../scripts/replications/README.md)
   生成一个薄的 `replicate.py`：读配置，调用 [`scripts/lib/`](../../scripts/lib/README.md) 的
   函数，通过 `VARReport` 保存产出。只有当它是对一个已核验字典条目
   （`verified.status: checked_against_paper` 或 `signed_off`）的干净经典复现时，新目录才放进
   `scripts/replications/`；否则放进 `scripts/applications/`。
4. 第 1 阶段只是简短的 1A 条目确认；跳过第 2 阶段（设定设计），因为设定已由字典条目确定。用户
   只需确认数据替代和任何有意的偏离。

从变量选择、识别到预期结果，一切都来自一个已对照论文核对过的条目。

## 模式 B：论文提交（先解析，再执行）

用户提交了一篇字典里还没有条目的论文（PDF 路径、URL、引用或纯文本）。例如：

- "这是一份 PDF，复现它。"
- "复现 Smith and Jones (2024, JME) 关于货币政策的研究。"
- "拿这篇 arXiv 论文，用到欧元区数据上。"

**路径：**按 [SKILL.md](SKILL.md#第-1b-阶段论文提交) 的第 1B 阶段进行：查重；核实暂存的文件
（先看 `papers/`，文件命名为 `<id>.pdf`）；起草条目；列出含糊之处（例如论文没有精确到季度的
样本起点，或只在正文里用文字给出的变量顺序）；新方法升级给 `advisor-protocol`；然后转入模式 A。
第 4 阶段把工作脚本写到 `scripts/applications/<id>/`；第 7 阶段确认最终层级。

每完成一篇论文，就多一个以后的会话可以复用的已核验字典条目。

## 模式 C：研究设计（依据模型自身知识）

用户提出开放的研究问题，没有点名具体方法或论文。例如：

- "货币政策如何影响产出和通胀？"
- "在欧元区数据里识别财政乘数，最好的办法是什么？"
- "我想研究大宗商品价格冲击的传导。"
- "中国的货币政策冲击对工业生产和 CPI 有什么影响？"

**路径：**

1. 针对问题、知识库和字典运行 `model-selection`。
2. **如果 model-selection 以高置信度找到一个或多个匹配的字典条目**，列出来并建议升级为模式 A。
3. **如果字典里没有匹配**，依据模型自身知识设计设定：选模型类别，提出变量和识别方式，推荐
   样本区间。标明每个决策的知识来源。
4. 完成设定设计并成功执行后，第 4 阶段默认把工作用的 `replicate.py` 写到
   `scripts/applications/<id>/`。最终处置（仅归档 / 保存为应用 / 提升为经典 / 继续迭代 / 丢弃）
   在**第 7 阶段（处置与归档）**确认。通过合理性检查的模式 C 运行，通常保存为应用，并可选地
   起草一个字典条目。新条目在其归属于论文的字段对照原文核对之前，保持
   `verified.status: draft`；`signed_off` 还要求用户批准这个核对过的条目。批准应用或其结果
   不会改变条目的状态。

这是 agent 独立推理最多的模式。字典作为参考，模型自身知识填补空白。

## 模式转换（详述）

模式不是单向的。会话可以中途在模式之间转换：

- **C → A**：model-selection 找到干净的字典匹配；升级为模式 A。
  *例：*用户问"货币政策如何影响产出？"，搜索找到 `cee_1999_monetary_svar` 和
  `sims_1980_var`，用户选 CEE → 切换到模式 A。
- **B → C**：论文提取失败，或方法太新、无法干净地对应；请用户改为描述研究问题。*例：*用户
  提交一篇 60 页的 DSGE 论文，其中的贝叶斯估计程序我们实现不了 → 问"你具体想从这篇论文里得到
  什么？"，再从那里开始设计。
- **A → C**：用户想对字典条目做很大的偏离，实际上是在设计新设定；降级为模式 C，以该条目作为
  起点参考。*例：*用户选了 CEE (1999)，但要求换掉 7 个变量中的 5 个；这是新设定，不是 CEE。
- **C → B**：用户在设计过程中找到一篇论文，想以它为锚。*例：*用户本来在从零设计，然后说
  "其实这篇论文正好做了这件事"，并上传了论文。

转换时总是明确告知：*"切换到模式 A：你的问题对应字典里的 CEE (1999)。要我运行那个设定吗？"*
在研究日志中记录每次转换及其触发原因。
