# 知识库

## 问题

agent 有两个知识来源，二者可能冲突：

1. **模型自身知识（parametric knowledge）。**模型在训练中学到的东西：教科书计量、经典论文、标准
   做法。它覆盖面广但很通用，而且偏向美国 / 欧洲的宏观。

2. **具体知识。**用户提供的东西：他们国家的经济结构、机构数据来源、政策制度、建模惯例、相关的
   本地文献。它覆盖面窄，但对当前情形是权威的。

没有明确的协调，agent 会默认使用模型自身知识，可能做出技术上正确、但对用户情形来说经济上错误的
选择。例如：

- 用户的国家有自己的统计机构，却推荐 FRED 序列。
- 国家实行钉住汇率，却假设汇率浮动。
- 某个变量在本地经济中是平稳的，却给它设随机游走的先验均值（`rw_deltas` 取 1）。
- 用户的央行运作方式不同，却按美国的制度时序选择 Cholesky 顺序。

## 设计原则：具体知识优先，模型自身知识补空白

完整的来源顺序（用户、字典、知识库、模型自身知识、数据驱动）在
[`specification/SKILL.md`](../specification/SKILL.md#decision-hierarchy) 中定义。在知识库与模型
自身知识之间：

1. **知识库有具体指引，就用它。**
2. **没有，就退回到模型自身知识。**
3. **不确定，就问用户。**
4. **始终公开每个决策的来源。**

## 知识库结构

知识库是由用户填充、按领域组织的一组文档。每个文档是 `knowledge-base/` 目录下的一个 Markdown
文件。

```
knowledge-base/
├── SKILL.md                 （本文件）
├── context/
│   ├── economy-profile.md   国家 / 经济体的结构描述
│   ├── data-sources.md      本地数据 API、数据库、文件位置
│   ├── conventions.md       机构的建模惯例
│   └── policy-regime.md     货币 / 财政框架、汇率制度
├── literature/
│   ├── paper-summaries/     用户核验过的相关论文摘要
│   └── methodology-notes/   来自论文的具体方法指引
└── priors/
    ├── variable-priors.md   关于变量行为的先验信念
    └── identification.md    偏好的识别策略及理由
```

（工作区里只带一个空的 `context/` 目录；其中的文件以及 `literature/` 和 `priors/` 目录在用户添加
材料时创建。插件升级不会改动 `context/`。）

### economy-profile.md

用户描述他们的经济体。这为模型选择、变量选择和合理性检查提供依据。模板：

```markdown
# 经济体概况

## 国家 / 地区
[例如：欧元区、智利、中国]

## 经济结构
- 开放 / 封闭：[小型开放经济 / 大型封闭 / ……]
- 汇率制度：[浮动 / 有管理的浮动 / 钉住 / 货币局]
- 资本账户：[开放 / 部分开放 / 封闭]
- 主导产业：[制造业、大宗商品、服务业、旅游业]
- 主要贸易伙伴：[……]

## 货币政策框架
- 工具：[政策利率 / 存款准备金率 / 汇率目标 / ……]
- 目标：[通胀目标制 / 货币总量 / 汇率 / 双重使命]
- 传导渠道：[利率 / 信贷 / 汇率 / 资产价格]
- 政策会议频率：[每月 / 每 6 周 / 每季度]
- 决策到实施的时滞：[立即 / ……]

## 财政框架
- 财政规则：[有 / 无，类型]
- 政府债务水平：[大致数值]
- 财政年度：[日历年 / 4 月至次年 3 月 / 10 月至次年 9 月]

## 已知的结构特征
- 美元化：[无 / 部分 / 完全]
- 非正规经济：[估计占比]
- 大宗商品依赖：[哪些商品，占出口 / GDP 的比重]
- 季节模式：[农业、旅游、财政周期、春节]

## 历史结构断点
- [日期]：[事件及其经济意义]
- [日期]：[事件]
```

**中国的提示：**起草中国的经济体概况时，常见要点包括：货币政策工具从数量型向价格型转变
（M2 增速目标 → 7 天逆回购利率、MLF、LPR），2005 年以来的有管理浮动汇率及 2015 年"8·11"汇改，
资本账户部分开放，春节的季节影响，以及国家统计局数据的口径断点。这些都要由用户核验，不能直接
当作定论。

### data-sources.md

把概念变量对应到本地数据来源。这会覆盖 data-retrieval skill 的默认来源（FRED）。模板：

```markdown
# 本地数据来源

## 主要统计机构
- 名称：[例如国家央行、智利国家统计局、Eurostat、国家统计局]
- API：[如有，写接口地址]
- 获取方式：[API / 批量下载 / 手工 / 内部数据库]

## 变量对应

| 概念              | 本地来源         | 序列 ID    | 频率 | 说明               |
|-------------------|-----------------|------------|------|--------------------|
| GDP（实际）        | [机构]          | [id]       | Q    | [基年、是否季调]    |
| CPI               | [机构]          | [id]       | M    | [篮子说明]          |
| 政策利率           | [央行]          | [id]       | D/M  | [哪个利率]          |
| 货币供应量         | [央行]          | [id]       | M    | [M1/M2/M3]         |
| 汇率              | [央行]          | [id]       | D    | [双边 / NEER]       |
| 失业率            | [机构]          | [id]       | M/Q  | [调查说明]          |
| ...               | ...             | ...        | ...  | ...                |

## 国际数据
- [还有哪些相关的国际来源：BIS、IMF IFS 等]

## 数据特点
- [例如：GDP 首次公布后修订幅度很大]
- [例如：失业调查在 2012 年改变了方法]
- [例如：CPI 篮子在 2019 年重新定基]
```

中国的情形下，国家统计局的指标可以直接写成 `nbs_m` / `nbs_q` / `nbs_a` 面板的列名，或者
`nbs` fetcher 的序列说明（`"频率|目录路径|指标键"`，见 data-retrieval skill）。

### conventions.md

机构的建模做法。模板：

```markdown
# 建模惯例

## 偏好的软件 / 语言
[例如：我们研究部门以 MATLAB 为标准 / 我们用 R / Python]

## 标准 VAR 设定
- 常用变量集合：[通常包含哪些变量]
- 常用滞后阶数：[例如季度 4 阶、月度 12 阶]
- 偏好的识别：[例如 Cholesky，慢变量在政策利率之前，快速金融变量在之后]
- 标准样本区间：[例如因制度变化从 2000Q1 开始]

## 先验惯例（如为贝叶斯）
- [例如：我们通常用 lambda_1 = 0.2 的 Minnesota 先验]
- [例如：我们把汇率视为 I(1)，把 CPI 视为趋势平稳]

## 报告标准
- [例如：始终报告 68% 和 90% 区间]
- [例如：脉冲响应期限 = 20 个季度]
- [例如：图表必须遵循内部风格：特定颜色、字体]

## 审稿预期
- [例如：审稿人期望看到对滞后阶数和样本区间的稳健性]
- [例如：我们部门偏好符号约束而非 Cholesky]
```

### policy-regime.md

足够详细地描述政策框架，让 agent 能做出合理的识别和合理性检查决策。模板：

```markdown
# 政策制度

## 当前制度
- 框架：[例如 2000 年以来的灵活通胀目标制]
- 工具：[例如隔夜双边回购利率]
- 目标：[例如整体 CPI 通胀 1–3%，中值 2.5%]
- 沟通：[例如通过政策声明提供前瞻指引]

## 历史制度
- [日期区间]：[制度描述]
- [日期区间]：[制度描述]

## 对建模的含义
- [例如：因制度变化，2000 年以前的数据不应与 2000 年以后的混合]
- [例如：1997 年以前汇率实际上是固定的，所以包含汇率的模型应从汇率浮动之后开始]
- [例如：2020 年以来的非常规政策措施可能影响利率传导]
```

### literature/ 目录

用户提供的论文摘要和方法笔记。agent 把它们当作权威依据之前，要由用户核验。

每篇论文摘要应包括：
- 引用信息
- 主要贡献（1–2 句话）
- 使用的模型 / 方法
- 与用户情形相关的主要发现
- agent 应采用的任何方法选择

## 各 skill 怎样查知识库

每个 skill 都遵循以下查找规程：

### 1. 先找具体指引

在做任何决策（变量选择、先验设置、识别、数据来源、合理性阈值）之前，skill 先查知识库：

```
decision_needed: "GDP 用哪个数据源？"

1. 读 knowledge-base/context/data-sources.md
   → 找到："实际 GDP 来自国家统计局，序列 <series id>"
   → 用这个。不要默认用 FRED。

2. 如果 data-sources.md 里没有：
   → 退回到模型自身知识（FRED、标准序列）
   → 告诉用户："你的知识库里没有指定本地 GDP 来源。默认使用 [FRED/IMF]。你可以把本地来源加到
     knowledge-base/context/data-sources.md。"
```

### 2. 检查冲突

有时模型自身知识和具体知识指向不同的方向。例如：

| 决策 | 模型自身知识 | 具体知识 | 处理 |
|----------|----------------|---------------|------------|
| 变量顺序 | 慢变量、政策工具、快变量（例如 CEE 1999 的时序） | 政策利率放最后（我们央行在数据公布后开会） | **具体知识优先** |
| GDP 先验 | 随机游走（`rw_deltas` = 1） | 趋势平稳（我们的 GDP 均值回复） | **具体知识优先** |
| 样本起点 | 1960Q1（观测最多） | 2000Q1（制度变化） | **具体知识优先** |
| 脉冲响应符号检查 | 价格之谜是危险信号 | 因汇率传递，预期会出现价格之谜 | **具体知识优先，但提出来讨论** |
| 滞后阶数 | 季度数据 4 阶 | 没有指引 | **模型自身知识补空白** |

### 3. 公开来源

在向用户提出的每个决策中，注明它来自具体知识还是模型自身知识：

> "我用的是国家统计局的实际 GDP 序列 [来自你的数据来源]。进口价格指数默认用 IMF IFS 的序列
> [模型自身知识；未指定本地来源]。要添加一个本地来源吗？"

这种透明度让用户能发现错误，并逐步填补知识库的空白。

### 4. 不确定时升级

如果 agent 遇到以下情况：
- 模型自身知识与具体知识明显冲突，并且
- 具体指引含糊或不完整

就问用户，而不是猜。这样措辞：

> "你的经济体概况写的是有管理的浮动汇率制度，但你的惯例中的识别策略假设汇率自由浮动。这次分析
> 我该按哪个来？"

## 填充知识库

### 初始设置

主控的第 0a 阶段负责设置，包括在运行不需要本地背景时跳过访谈的快速通道（见
[`orchestrator/SKILL.md`](../orchestrator/SKILL.md#第-0a-阶段知识库初始化一次性)）。按上面的模板
起草每个文档，交给用户审阅，保存确认后的版本。知识库跨会话保留。

### 逐步更新

在用户使用框架的过程中：

- 随时可以把新论文加到 `literature/`。
- agent 可以建议更新："你的分析用了一个知识库里没有的数据源。要我把它加进去吗？"
- 每次分析完成后，提议根据会话中做出的选择更新惯例。

### 来自上传的论文

用户提供一篇论文（PDF 或引用）时：

1. agent 提取与知识库相关的方法选择。
2. 给出摘要请用户核验。
3. 确认后，保存到 `literature/paper-summaries/`；如果论文包含本地经济信息，同时更新相关的背景
   文件。

这与顾问规程不同：顾问处理数学推导；知识库处理背景和方法上的选择。

## 与其他 skill 的配合

| skill | 查什么 | 知识库来源 |
|-------|-----------------|----------------------|
| 模型选择 | 经济结构、制度、惯例 | economy-profile、policy-regime、conventions |
| 数据获取 | 本地数据来源、变量对应 | data-sources |
| 设定：BVAR 先验 | 先验信念、变量处理（I(1) 还是 I(0)） | variable-priors、conventions |
| 设定：区块外生性 | 要视为外生的外国区块（小型开放经济） | economy-profile |
| 设定：符号约束 | 本经济体中冲击的预期符号 | identification、literature |
| 设定：TVP-VAR | 已知的结构断点日期 | economy-profile、policy-regime |
| 设定：局部投影 | 与本经济体相关的工具变量 | literature、identification |
| 诊断 | 本经济体的合理性基准 | economy-profile、conventions |
| 顾问规程 | 推导时要参考的论文 | literature/methodology-notes |
| 研究日志 | 记录每个决策依据的知识来源 | 全部 |

## 示例：小型开放经济的 Sims (1980) 式 VAR

没有知识库时，agent 使用 FRED 数据、论文中的 Cholesky 顺序，以及基于美国宏观直觉的合理性检查。
有知识库时，同样的工作流会使用本地数据（data-sources.md），加入汇率和一个外生的外国区块
（economy-profile.md；见 specification skill 的区块外生性步骤），按本地政策时序调整 Cholesky
顺序（conventions.md），把汇率视为 I(1)、把政策利率视为 I(0)（variable-priors.md），从采用通胀
目标制之时开始样本（policy-regime.md），并可能因汇率传递而预期出现价格之谜（economy-profile.md、
literature/）。
